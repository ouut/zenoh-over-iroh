# 生产部署检查清单

> 完整方案从开发到上线的全部步骤。

---

## 第一步：理解当前局限

**核心发现**：zenoh 1.9 不支持在运行时动态注册传输层 scheme。
`"iroh/"` 被 zenoh 解析 locator 时是无法识别的——它需要作为内置传输层编译到 zenoh 中。

## 第二步：正确的生产方案（二选一）

### 方案 A：编译内置传输层（推荐）

把 `zenoh-link-iroh` 做成和 `zenoh-link-tcp`、`zenoh-link-quic` 一样的编译时传输层。

```diff
# 在 zenoh 的 Cargo.toml 中（fork）
  [dependencies]
+ zenoh-link-iroh = { git = "https://github.com/ouut/zenoh-over-iroh" }
```

```diff
# 在 zenoh/src/lib.rs 中
  pub use zenoh_link_quic::*;
+ pub use zenoh_link_iroh::*;
```

之后 `"iroh/..."` 就是 zenoh 的原生 scheme 了，和 `"tcp/..."`、`"quic/..."` 平级。

### 方案 B：Iroh 桥接器（独立进程）

运行一个 Iroh ↔ Zenoh TCP 桥接进程：

```
┌────────┐  TCP   ┌──────────────┐  Iroh P2P  ┌────────┐
│ Zenoh  │←──────→│ Iroh Bridge  │←──────────→│ Iroh   │
│ 节点 A  │        │ (本进程)     │             │ 节点 B  │
└────────┘        └──────────────┘             └────────┘
```

bridge 两端各自用 `zenoh::open("tcp/...")` 连接，中间用 iroh 连接。
Iroh 的 path migration 由 `LinkStateMachine` 管理。

## 第三步：当前代码能做什么

| 组件 | 可以直接用？ | 说明 |
|------|:---:|------|
| `zenoh-link-state` crate | ✅ | `cargo add` 即可，纯算法库 |
| `LinkStateMachine` | ✅ | 任何 Rust 项目直接使用 |
| `libzenoh_link_iroh.so` | ⚠️ | 可被 zenohd 加载，但 `"iroh/"` scheme 未注册 |
| `libzenoh_over_iroh.so` | ✅ | 把 Iroh 作为独立传输层使用（非 zenoh 集成） |
