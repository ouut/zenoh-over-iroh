# 内网扫码直连方案 — Iroh P2P + QR Code

> 手机扫码 → 获取 NodeID → Iroh 直连 → Zenoh pub/sub
> 不需要配 IP/端口，不需要多播，WiFi 切换不中断

---

## 为什么不用 TCP 多播？

| 方案 | 问题 |
|------|------|
| TCP 手动配 IP | 手机 DHCP 换 IP 就断 |
| UDP 多播 | 很多 WiFi AP 禁用多播、丢包严重 |
| mDNS | 同样依赖多播，不稳定 |

## Iroh 方案

```
手机A (扫码)                    手机B (显示二维码)
    │                                │
    │  scan QR → NodeID: abc12...    │  显示: NodeID=abc12...
    │                                │
    └──── iroh.connect(abc12) ──────→│
              │                      │
        QUIC P2P (直连优先, Relay 保底)
              │                      │
    ┌─────────┴──────────┐           │
    │  Zenoh Session      │←─────────┘
    │  pub("room/msg")   │
    │  sub("room/msg")   │
    └────────────────────┘
```

**NodeID 不变**：WiFi → 4G 切换，NodeID 不变，连接不断。

---

## 示例: 内网3人聊天室

### 第1步: 启动 Relay（每局域网一个，或共用公网 Relay）

```bash
# 内网部署 iroh-relay（开发模式）
/tmp/iroh-relay --dev
# 输出: listening on http://0.0.0.0:3340
```

### 第2步: 各节点启动 + 自动发现

```rust
// 节点 A — 生成 NodeID，显示二维码让 B/C 扫
use iroh::Endpoint;

let ep = Endpoint::builder()
    .discovery_n0()                            // 自动发现 relay
    .relay_url("http://192.168.1.100:3340".parse()?)  // 局域网 relay
    .bind().await?;

let node_id = ep.node_id();
// 生成二维码: qrencode -o qr.png "iroh:${node_id}"
println!("我的 NodeID: {node_id}");  // 显示二维码
```

```rust
// 节点 B/C — 扫码后连接 A
let ep = Endpoint::builder()
    .discovery_n0()
    .relay_url("http://192.168.1.100:3340".parse()?)
    .bind().await?;

// 扫码获取的 NodeID
let peer: NodeId = "abc123...".parse()?;
ep.connect(peer, b"zenoh/1.0".to_vec()).await?;
```

### 第3步: 通过 Zenoh pub/sub 聊天

连接建立后，Zenoh 在这条 Iroh 链路上做 pub/sub：

```rust
let session = zenoh::open(config).await?;

// 所有人订阅同一个 key
let sub = session.declare_subscriber("chat/lobby").await?;

// 任何人发布消息，所有人收到
session.put("chat/lobby", "hello 大家好").await?;
```

### 完整流程

```
时间线:

t=0   A 启动 → NodeID: abc123 → 显示二维码
      B 启动 → 扫码 abc123 → iroh.connect(abc123)
      C 启动 → 扫码 abc123 → iroh.connect(abc123)

t=1   A/B/C 之间 Iroh 连接建立
      每条连接内部有 LinkStateMachine

t=2   zenoh session 启动，通过 Iroh link 互联
      pub("chat/lobby", "hello") → 所有人收到

t=5   B 切 WiFi→4G (IP 变了)
      B↔A 的 Iroh 连接: QUIC 路径迁移 → LSM 进入 Migrating
      B↔A 的 Zenoh: B 发的消息排队，恢复后自动发送
      B↔C: 同理

t=8   B 恢复 → LSM → Connected → 排队消息自动发出
      上层完全无感知
```

## 代码: 简易内网聊天 (Python + 扫码)

```python
#!/usr/bin/env python3
"""内网扫码聊天 — iroh discovery + zenoh pub/sub"""

import subprocess, sys, qrcode, io

# 1. 启动本地 iroh-relay
relay = subprocess.Popen(["/tmp/iroh-relay", "--dev"])

# 2. 启动 Rust chat (内嵌 iroh + zenoh)
chat = subprocess.Popen(
    ["../09_chat_room/target/release/chat", sys.argv[1]],
    stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True
)

# 3. 从 stderr 提取 NodeID
for line in chat.stderr:
    if "NodeID:" in line:
        node_id = line.split("NodeID:")[1].strip()[:64]
        break

# 4. 生成二维码 (终端显示)
qr = qrcode.QRCode()
qr.add_data(f"iroh:{node_id}")
qr.print_ascii()  # 终端显示二维码

print(f"\nNodeID: {node_id}")
print("让其他人扫描此二维码加入聊天")

# 5. 主循环
while True:
    msg = input("> ")
    chat.stdin.write(msg + "\n")
    chat.stdin.flush()
```

## 为什么 Iroh 比多播好？

| 场景 | UDP 多播 | Iroh |
|------|:---:|:---:|
| 企业 WiFi (禁用多播) | ❌ 不可用 | ✅ Relay 保底 |
| 跨 VLAN | ❌ 不可达 | ✅ Relay 可达 |
| IP 变化 (WiFi→4G) | ❌ 断开 | ✅ QUIC 迁移 |
| NAT 后 | ❌ 不可达 | ✅ 打洞直连 |
| 配置 | 手动配 IP:Port | **零配置，扫二维码** |
